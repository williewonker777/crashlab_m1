CONCEPT

VLA 세 글자

인식과 해석에서 행동 출력까지 하나의 흐름

CONCEPT · POLICY

Policy: 관측과 명령에서 행동으로

VLA는 매 순간의 관측과 명령을 받아 다음 행동을 고르는 Policy(행동을 선택하는 규칙)이다.

  1. 관측 oₜ · 지금의 상황

    카메라 영상과 관절 각도 같은 로봇 상태다. 무엇이 보이고 로봇이 어떤 자세인지를 담는다.

  2. 명령 l · 사람이 준 작업

    작업을 설명하는 문장이다. 한 Episode(작업 한 번을 시작해서 끝낼 때까지) 동안 보통 바뀌지 않는다.

  3. 행동 aₜ · 다음 순간의 목표

    관절 목표각이나 손끝 이동량이다. 모터 전류는 직접 정하지 않고, 강의 ②의 제어기가 이 값을 목표로 따라간다.

Policy π(aₜ | oₜ, l): 관측과 명령이 주어졌을 때의 행동 분포. VLA는 신경망(데이터로 계산법을 배우는 모델)으로 이 함수를 학습한다.

Policy: 관측과 명령을 다음 행동으로 바꾸는 함수

CONCEPT

기존 방식과의 차이

  • 모듈형은 단계마다 사람이 규칙과 인터페이스를 정한다.
  • VLA는 영상·명령에서 행동까지 한 모델로 학습한다.
  • 모듈형은 원인 추적이 쉽고, VLA는 새 물체·표현에 유연하다.
  • 두 방식 모두 마지막 제어 단계는 그대로 둔다.

WHY VLA

VLA를 쓰는 이유

인터넷 규모의 Pretraining(미리 넓게 배우는 학습)으로 얻은 시각·언어 지식을 로봇 행동에 연결한다.

COMPARE

VLA의 강점과 한계

강점

  • 처음 보는 물체·문장에도 의미를 연결한다.
  • 명령 문장만 바꿔 여러 작업을 수행한다.
  • 공개 모델을 Fine-tuning(우리 데이터로 추가 학습)해 시작할 수 있다.

한계

  • 새로운 동작은 로봇 데이터에서만 배운다.
  • 큰 모델은 느리다. RT-2는 Parameter(학습된 숫자)가 550억 개(55B)이고, 1초에 1~3번(1~3 Hz) 행동을 냈다.
  • 성공률을 높여도 안전을 보장하지는 않는다.

COMPARE

모방학습 vs 강화학습

모방학습

  • 전문가 시연을 보고 그대로 따라 하도록 배운다.
  • 양질의 시연 데이터가 많을수록 유리하다.
  • VLA 학습의 기본이며 Behavior Cloning이라고도 한다.

강화학습

  • 시행착오를 겪으며 받는 보상의 합이 커지도록 배운다.
  • 보상 설계가 잘못되면 의도와 다른 Policy가 학습된다.
  • 최근에는 시연으로 배운 VLA를 다듬는 데 쓴다.

CONCEPT · BEHAVIOR CLONING

Behavior Cloning과 누적 오차

시연을 따라 하는 Policy는 작은 실수 뒤의 상황을 배운 적이 없다.

  1. Behavior Cloning

    시연에서 얻은 관측–행동 쌍을 정답으로 삼아 지도학습(정답이 있는 예제로 배우는 학습)한다. VLA 학습의 기본 방식이다.

  2. Distribution Shift · 배운 적 없는 상황

    조금 벗어난 상태는 학습 데이터에 없어서 다음 행동도 틀리기 쉽다. 강의 ③의 Drift처럼 오차가 점점 쌓인다.

  3. 완화 방법

    다양한 시작 조건, 실수 뒤 복구하는 시연, 사람이 개입한 기록, 행동 묶음 예측을 사용한다.

CONCEPT · TOKEN

Token: 모든 입력을 같은 형식으로

영상·문장·로봇 상태를 한 줄의 Token으로

GUIDE · TOKEN

Token을 만드는 구성 요소

Token모델이 한 칸씩 읽는 입력 조각이다. 문장·영상·로봇 상태가 모두 Token이 되어 한 줄로 이어진다.
Vector순서가 정해진 숫자 목록이다. Token 하나는 Vector 하나가 되며, PaliGemma에서는 숫자 2048개다.
Tokenizer문장을 사전에 있는 조각으로 자르고 번호를 붙인다. PaliGemma는 ‘빨간 컵을 집어’를 띄어쓰기를 포함해 7조각으로 자른다.
Embedding조각 번호를 Vector로 바꾸는 표다. 번호마다 숫자 목록이 있고, 그 값은 학습으로 정해진다.
Vision Encoder영상을 작은 정사각형 조각으로 나눠 조각마다 Vector를 만드는 신경망이다. 224×224 영상은 조각 256개다.
TransformerToken끼리 서로 얼마나 참고할지 계산해 정보를 섞는 신경망이다. 이 계산 층을 여러 겹 쌓는다.

Token은 원래 문장 조각을 부르던 말이다. 영상·상태도 같은 줄에서 읽으므로 Token이라 부른다. 문장은 Tokenizer로 조각·번호를 만들고, 영상·상태는 Vision Encoder와 선형 변환으로 Vector를 만든다.

CONCEPT · LINEAR PROJECTION

선형 변환: 곱하고 더해 길이 맞추기

길이가 다른 숫자 목록을 모델이 쓰는 길이로 바꾸는 가장 단순한 계산이다.

  1. 계산 · 곱하고 더하기

    출력마다 가중치를 입력에 곱해 모두 더한다. 같은 점수에 대학마다 다른 비율을 곱해 환산 점수를 내는 계산과 같다.

  2. 쓰임 · 길이 맞추기

    π0·SmolVLA는 관절 상태를 선형 변환으로 Token 하나로 만든다. PaliGemma는 Vision Encoder의 숫자 1152개를 2048개로 맞춘다.

  3. 학습 · 가중치는 데이터로

    가중치는 사람이 정하지 않고 학습으로 정해진다. 관절값 8개를 숫자 1024개로 바꾸면 곱할 가중치만 8,192개다.

곱셈과 덧셈만 쓰기 때문에 선형이라 부른다. 신경망은 선형 변환 사이사이에 곡선을 만드는 계산을 끼워 복잡한 관계를 배운다.

곱셈과 덧셈으로 숫자 목록의 길이를 맞추는 변환

ARCHITECTURE · ACTION MODULE

행동 생성 모듈의 두 가지 구조

둘 다 VLM이 읽은 영상·문장 정보를 참고해 행동 묶음을 만드는, 행동 전용의 작은 Transformer다.

π0 · Action Expert

π0가 붙인 이름으로, 한 Transformer 안에서 상태·행동 Token만 맡는 작은 가중치 묶음이다. 영상·문장 Token은 큰 VLM 가중치가 계산하고, Action Expert는 층마다 그쪽을 참고한다. 이름은 입력에 따라 담당 모듈을 나누는 MoE(Mixture of Experts)에서 왔다.

GR00T N1 · Diffusion Transformer

DiT(Diffusion Transformer)는 무작위 값을 다듬는 과정을 Transformer로 계산하는 구조로, 2022년 이미지 생성용으로 나왔다. GR00T N1에서는 VLM과 따로 둔 DiT가 VLM Token을 참고해 행동을 만들며, Flow Matching으로 학습한다. 입력의 Noise 섞인 행동은 처음엔 무작위 값이고, 다듬을 때마다 행동에 가까워진다.

따로 두는 이유 · π0는 영상·문장 쪽 계산 결과를 저장해 두고 Action Expert만 10번 다시 계산한다. RTX 4090에서 전체 73 ms 중 행동 다듬기 10번은 27 ms다. 로봇 Token에 별도 가중치를 쓰자 성능도 올랐다고 보고했다.

Noise(데이터에 섞는 무작위 값) · 학습 때는 시연 행동에 Noise를 섞어 놓고 원래 행동 쪽으로 돌아가는 방향을 맞히게 한다. 실행 때는 무작위 값에서 시작해 π0는 10번, GR00T N1은 4번 다듬는다. Diffusion(‘확산’) 모델은 섞은 Noise를, Flow Matching은 행동 쪽 방향을 맞힌다. 숫자 예시는 뒤 장에서 따라가 본다.

상황을 읽는 VLM과 행동을 만드는 작은 Transformer의 분업

ARCHITECTURE · ACTION HEAD

Action Head의 자리: 수집·학습·실행

Action Head는 데이터 수집 때 사람이 로봇 제어기에 보내던 목표를 대신 만든다. 목표를 따라가는 제어기는 그대로다.

  1. 01 · COLLECT수집

    원격 조작에서는 리더 팔(사람이 손으로 움직이는 같은 모양의 조종용 팔)의 관절각이 로봇 제어기의 목표가 된다. 이 목표가 행동으로, 같은 시각의 영상·관절 상태가 관측으로 저장된다.

  2. 02 · TRAIN학습

    로봇 없이 저장된 데이터로 학습한다. 같은 관측·명령에서 Action Head가 낸 행동과 기록된 행동의 차이를 줄이도록 가중치를 고친다. Backbone은 함께 고치기도 하고(OpenVLA) 고정하기도 한다(SmolVLA).

  3. 03 · DEPLOY실행

    사람 자리에 VLA가 들어가 같은 형식의 목표를 같은 제어기로 보낸다. 그래서 행동의 의미·단위·주기가 수집 때와 같아야 한다.

Action Head 끝에도 선형 변환이 있다. π0는 폭 1024의 Vector를 행동 숫자 개수로 줄여 내보낸다. OpenVLA는 따로 붙이지 않고 언어 모델이 단어를 고르듯 구간 번호를 고른다.

수집 때 사람이 보내던 목표를 대신 만드는 Action Head

ARCHITECTURE · ACTION SPACE

Action Space: 무엇을 출력하나

Action Space(행동값의 형식과 범위)와 실행 주기를 정해야 학습 데이터와 제어기가 맞물린다.

  1. 표현 · 관절 또는 손끝

    관절 목표각은 제어기에 바로 들어간다. 손끝 변화량은 IK(역기구학: 손끝 목표로 관절각을 거꾸로 푸는 계산)를 거쳐 관절각으로 바꿔야 한다. 관절도 절대 각도 대신 현재 각도와의 차이로 내보내기도 한다.

  2. 정규화(값의 범위 맞추기)

    차원마다 단위와 범위가 다르다. 학습 데이터의 평균·표준편차나 Percentile(분포에서의 상대적 위치)로 비슷한 범위에 맞춘다. 실행 때는 같은 통계로 출력을 원래 단위로 되돌린다.

  3. 주기 · 기록과 실행의 일치

    데이터를 기록한 주기와 실행 주기를 같게 둔다. 다르면 같은 행동이 다른 속도로 실행된다.

행동의 의미·단위·주기를 데이터와 제어기에서 동일하게

ARCHITECTURE · ACTION HEAD

행동 생성 방식 세 가지

같은 VLM Backbone을 써도 행동을 내보내는 방식에 따라 속도·정밀도·학습 목표가 달라진다.

A · DISCRETE TOKEN

Discrete Token

행동값을 구간 번호로 바꿔 단어처럼 하나씩 생성한다. 언어 모델의 구조와 학습 방법을 그대로 쓴다.

RT-2 · OpenVLA · π0-FAST

B · DIFFUSION · FLOW

Diffusion · Flow Matching

학습 때는 시연 행동에 Noise를 섞고 원래 행동 쪽 방향이나 섞은 Noise를 맞힌다. 실행 때는 Noise에서 시작해 행동 묶음을 여러 번 다듬는다. 연속값과 정답이 여럿인 행동을 다룬다.

Diffusion Policy · Octo · π0 · GR00T

C · REGRESSION

Regression

연속값을 한 번의 계산으로 바로 출력한다. 빠르지만 정답이 여럿이면 평균에 가까운 값을 낼 수 있다.

CONCEPT · MULTI-MODAL DISTRIBUTION

평균 행동의 함정

Multimodal Distribution(올바른 행동이 여러 갈래인 분포)에서는 평균을 내는 학습이 둘 다 아닌 행동을 만든다.

  1. Multimodal Distribution · 정답이 여럿

    여기서 Multimodal은 입력 종류(영상·문장)가 아니라 정답이 여러 갈래라는 뜻이다. 왼쪽·오른쪽 우회가 모두 올바른 시연이다.

  2. 평균의 문제

    오차 제곱을 줄이는 Regression은 두 경로의 중간을 출력한다. 그 중간이 장애물이다.

  3. 생성 모델 · 분포에서 하나를 선택

    Diffusion·Flow Matching은 행동의 분포를 배워 한쪽 경로를 뽑고 끝까지 따라간다.

개념도. 실제 성능은 작업과 데이터에 따라 다르다. Regression을 쓰는 OpenVLA-OFT도 높은 성공률을 보고했다.

ACTION HEAD · NOISE

Noise를 섞어 배우는 방법

Diffusion·Flow Matching은 정답 행동에 일부러 Noise를 섞어 놓고, 거기서 정답 쪽으로 돌아가는 방향을 맞히는 연습을 한다. 실행 때는 Noise에서 출발해 배운 방향으로 조금씩 옮겨 행동을 만든다.

  1. 학습 한 번 · 섞고 방향 맞히기

    시연 행동 a와 무작위 Noise ε를 비율 τ(0이면 Noise, 1이면 정답)로 섞은 점 x를 만들고, a − ε를 정답 방향으로 맞히게 한다. 예시는 정답 1.6에 예측 1.2라 손실이 0.16이다. 학습마다 시연·Noise·τ를 새로 뽑아 한 번만 계산한다.

  2. 실행 · Noise에서 여러 번 이동

    실행 때는 정답이 없으니 새로 뽑은 Noise에서 출발해 예측한 방향으로 0.1씩 10번 옮긴다(π0). 앞 장의 「다듬기 10번」이 이 반복이다.

  3. 여러 번 나누는 이유 · 평균 피하기

    출발점에서 예측하는 방향은 정답들의 평균을 가리킨다. 한 번에 끝까지 가면 제곱 오차 Regression처럼 평균에 떨어진다. 조금씩 옮기며 방향을 다시 계산하면 출발한 Noise에 따라 한쪽 정답으로 간다.

Diffusion 모델은 방향 대신 섞은 Noise 자체를 맞힌다. 섞어서 배우고 여러 번 다듬는 흐름은 같다.

정답에 Noise를 섞어 돌아오는 방향을 배우고, 실행 때는 여러 번 나눠 이동

Flow Matching(무작위 값에서 정답으로 가는 방향을 배우는 방법)은 π0·GR00T·SmolVLA의 연속 행동 생성 방식이다.

  2. 생성 · 반복 이동

    Noise에서 출발해 예측한 방향으로 조금씩 이동한다. π0는 10번 반복한다.

INFERENCE · PIPELINE

Inference Pipeline: 모델 출력에서 모터까지

VLA는 관절 목표까지만 만든다. 목표를 모터 전류로 바꾸는 일은 로봇 쪽 프로그램과 강의 ②의 제어기가 맡는다.

  1. 01 · MODEL모델 쪽

    Action Head의 출력은 학습 때처럼 정규화된 숫자다. 저장해 둔 통계로 rad 같은 원래 단위로 되돌린다. 관절 변화량으로 학습했다면 현재 관절각을 더해 목표각을 만든다.

  2. 02 · ROBOT로봇 쪽

    로봇 프로그램이 Chunk를 받아 제어 주기마다 하나씩 보낸다. openpi(π0 공개 코드)의 ALOHA 예제는 50 Hz로 25개를 실행한 뒤 새 Chunk를 요청한다. 현재 자세에서 너무 먼 목표는 잘라낸다.

  3. 03 · CONTROL제어기

    제어기가 목표와 현재 각도의 차이로 토크를 정하고 드라이버가 전류를 맞춘다. ALOHA는 모터 안의 PID가 행동 주기보다 빠르게 목표를 따라간다.

모델을 팀 서버 같은 GPU 컴퓨터에서 돌리면 로봇 프로그램이 네트워크로 관측을 보내고 Chunk를 받는다. 이 통신 시간도 Inference 지연에 더해진다.

    Chunk를 실행한 뒤 멈추고 다음 Inference를 기다린다. 지연만큼 로봇이 정지한다.

  2. 비동기 실행(실행과 계산을 동시에)

    실행하는 동안 다음 Chunk를 미리 계산한다. SmolVLA는 이 방식으로 작업 시간이 13.75초에서 9.7초로 줄었다고 보고했다.

  3. Chunk 경계의 연결

    새 Chunk에서 이미 지나간 d개는 버린다. RTC(Real-Time Chunking)는 실행이 확정된 행동을 고정하고 나머지를 이어서 생성해 경계의 끊김을 줄인다.

CONCEPT

시뮬과 실물의 간극

  • 실물 센서에는 항상 Noise가 있다. Sim-to-Real(시뮬에서 배운 것을 실물로 옮기기)에서는 이 차이가 문제가 된다.
  • 마찰과 지연도 시뮬과 일치하지 않는다.
  • 조명 변화까지 더해지면 Policy 성능이 저하된다.

SIM-TO-REAL

간극을 줄이는 방법

Domain Randomization조명·색·마찰·질량·카메라 위치를 학습 중 무작위로 바꿔 특정 값에 맞춰지지 않게 한다.
시뮬·실물 함께 학습많은 시뮬레이션 데이터와 적은 실물 데이터를 섞어서 학습한다. (Co-training)
실물 Fine-tuning시뮬레이션에서 학습한 모델을 실물 시연으로 다시 학습한다. 이번 학기의 진행 순서다.
관측·행동 일치카메라 위치·해상도, 제어 주기, 행동 단위를 시뮬레이션과 실물에서 같게 맞춘다.

ROBOT MODEL · CONCEPT

URDF · 링크와 관절

Unified Robot Description Format · XML 문법으로 링크와 관절 기술

실제 전체 링크를 생략한 개념도다. 최상위 <robot name="alice_m1"> 안에 link와 joint를 선언한다.

  1. link · 하나의 강체

    몸통·팔·손가락처럼 함께 움직이는 강체 단위다.

  2. joint · 링크 사이의 연결

    parent와 child를 지정하고 고정·회전·직선 운동을 정한다.

  3. tree · 루트와 분기 구조

    각 child는 하나의 parent에 연결된다. 그리퍼의 닫힌 고리는 별도로 다룬다.

링크 좌표계와 관절축

  1. joint origin

URDF · BUILD 1

조립도 기반 fixed joint 작성

WRIST1 아래 −73 mm 위치에 WRIST2 배치 · Z축 기준 +90° 회전

<joint name="l_wrist2" type="fixed">
  <origin xyz="0 0 -0.073"
          rpy="0 0 1.57079632679"/>
  <parent link="left_arm_link_7"/>
  <child link="left_wrist2_link"/>

실제 URDF의 l_wrist2 발췌. 부모·자식 링크 선언은 생략했다.

  1. 73 mm → 0.073 m

    부모의 −Z 방향이므로 xyz의 z에 −0.073을 기록한다.

  2. 90° → 1.5708 rad

    URDF의 rpy에는 각도를 rad로 기록한다. 이 모델은 +90°를 사용한다.

  3. fixed · 자유도 없는 고정 연결

    WRIST2는 손목에 고정된 구성 요소다. 별도의 모터가 달린 회전관절이 아니다.

조립 위치는 origin, 운동 방식은 joint type으로 구분

URDF · BUILD 2

회전관절의 축과 한계 설정

WRIST2 아래 93.5 mm 위치에서 INPUT 관절 프레임의 X축 회전

  1. revolute · 범위가 있는 회전

    lower·upper는 rad 단위다. 1.3125 rad는 약 75.2°다.

  2. axis · 회전의 양의 방향

    오른손 법칙으로 확인한다. 실제로는 손목을 +90° 돌려 조립하므로, 부모 손목 기준으로 보면 축 방향이 달라진다.

  3. effort·velocity · 모델의 한계 필드

    회전관절에서는 N·m와 rad/s를 사용한다. 기록된 값이 장비의 안전 허용값을 보장하지는 않는다.

<joint name="l_gripper_input" type="revolute">
  <origin xyz="0 0 -0.0935" rpy="0 0 0"/>
  <parent link="left_wrist2_link"/>
  <child link="left_gripper_input_link"/>
  <axis xyz="1 0 0"/>
  <limit lower="0.0" upper="1.3125"
         effort="1000" velocity="3.0"/>
</joint>

실제 URDF 발췌. effort=1000은 파일의 값이며 실기 구동 권장값이 아니다.
