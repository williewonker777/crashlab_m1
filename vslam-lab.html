토픽에서 시작하는
Visual SLAM 구현

ALICE M1의 영상·깊이·카메라 정보를 받아 위치를 추정하고 지도를 만든다. 같은 장소를 다시 관측하면 과거의 자세도 보정한다. 여섯 실습의 코드는 하나의 프로그램으로 이어진다.

01 · 입력과 동기화02 · 특징점과 3차원 점03 · 이동 추정과 VO04 · 키프레임과 지도05 · 루프와 그래프 보정06 · 재현과 평가

무엇을 직접 개발하는가

  1. 관측영상에서 같은 점을 찾는다
  2. 이동 추정카메라의 자세 변화를 구한다
  3. 지도 생성관측한 점을 같은 공간에 모은다
  4. 재방문 보정자세와 지도의 누적 오차를 줄인다

기본 과제는 RGB-D Visual SLAM이다. RGB-D는 색상 영상과 깊이 영상을 함께 사용하는 방식이다. 이 환경에서는 깊이가 이미 제공되므로, 깊이 생성 이후의 위치 추정·지도 생성·재방문 보정을 구현한다. 강의의 스테레오 원리는 깊이가 만들어지는 한 방법으로 연결해 이해한다.

ORB(Oriented FAST and Rotated BRIEF), PnP(Perspective-n-Point), RANSAC(Random Sample Consensus), 수치 최적화 함수는 OpenCV·SciPy 등의 라이브러리를 사용해도 된다. 데이터 연결, 대응점 구성, 변환 누적, 실패 판정, 키프레임 관리, 루프 검증, 그래프 잔차와 지도 갱신은 학생이 설계한다.

기본 구현은 머리 자세를 고정한 평면 주행 데이터를 사용한다. 프론트엔드의 카메라 이동은 3차원으로 추정하고, 백엔드의 포즈 그래프는 x·y·yaw를 최적화하는 SE(2)로 시작한다. 머리 운동·6자유도 SE(3) 최적화·IMU 융합·Nav2 연동은 확장 과제다.

수업의 시작점

교수자가 ALICE M1 프로그램과 센서 발행을 실행한 상태다. 학생은 현재 토픽에 자신의 구독 노드를 연결한다. 완성형 SLAM 패키지를 실행하는 단계 대신, 아래 모듈을 차례로 작성한다.

개발 노드의 입출력 규약

ROS 2 Jazzy 환경에서 Python 또는 C++로 작성한다. Python 예시 의존성은 rclpy, message_filters, cv_bridge, tf2_ros, OpenCV, NumPy, SciPy다. 이미 제공된 ROS 환경을 먼저 확인한다.

student_vslam/
  input.py       # 보정 정보 캐시, RGB-D 동기화, 데이터 검증
  frontend.py    # 특징점, 매칭, 3D–2D 대응, PnP
  odometry.py    # 변환 누적, 몸체 변환, 추적 상태

여러 조가 같은 그래프를 쓸 때는 접두어와 프레임을 조별로 구분한다. 학생 노드는 기존 map → odom → base_footprint TF를 발행하지 않는다. 기본 과제는 메시지 출력으로 검증한다. RViz(ROS Visualization)의 Fixed Frame을 student_odom으로 두고 VO를, student_map으로 두고 지도·보정 궤적을 각각 확인한다. 두 결과의 중첩 비교는 저장한 궤적을 같은 초기 기준으로 맞춰 그린다.

Path의 각 자세 시각은 해당 관측 시각이다. Odometry에서 계산하지 않은 속도나 공분산을 정확한 측정값처럼 해석하지 않는다. 기본 평가는 pose/path와 별도 품질 로그를 사용한다.

01 · 입력과 동기화

개념: 영상의 한 픽셀과 깊이의 한 픽셀이 같은 지점·같은 시각을 가리켜야 3차원 점을 만들 수 있다. 서로 다른 시각의 자료를 섞으면 움직이는 카메라의 관측이 어긋난다.

먼저 확인할 명령

ros2 topic list -t
ros2 topic info -v /aeirobot/vslam_left_image
ros2 topic info -v /aeirobot/vslam_depth
ros2 topic info -v /aeirobot/vslam_left_camera_info
ros2 topic echo /aeirobot/vslam_left_camera_info --once --qos-reliability best_effort
ros2 topic hz /aeirobot/vslam_left_image
ros2 topic hz /aeirobot/vslam_depth

hz는 충분히 관찰한 뒤 Ctrl+C로 종료한다. 토픽이 보이지 않으면 교수자가 제공한 동일 ROS 환경·호스트/컨테이너에서 실행 중인지 확인한다. 관측한 호스트는 ROS_DOMAIN_ID=122, RMW_IMPLEMENTATION=rmw_cyclonedds_cpp, ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST였다. 이 설정에서는 다른 컴퓨터에서 도메인 번호만 맞춰도 자동으로 연결되는 것은 아니다.

구현 순서

  1. CameraInfo를 별도로 구독해 저장한다. 크기·K·D·R·P·frame_id를 검사하고, 보정 정보가 도착하기 전에는 프레임 처리를 시작하지 않는다.
  2. RGB와 깊이 구독에 동일한 BEST_EFFORT / VOLATILE QoS를 사용한다. 헤더 시각으로 동기화한다. 예시 시작값은 ApproximateTimeSynchronizer([rgb, depth], queue_size=10, slop=0.02)다.
  3. 허용 시각 차이는 실제 로그로 검증한다. 현재 관측에서는 동일 시각 쌍이 있었으므로 20 ms 이내에서 시작한다. 쌍이 적다는 이유로 0.1~0.3초 전 깊이까지 섞지 않는다. 각 입력 수와 동기화 성공 수를 따로 센다.
  4. cv_bridge로 RGB를 rgb8, 깊이를 passthrough로 읽는다. 현재 32FC1은 32비트 실수 1채널이며 카메라 Z축 방향의 깊이(m)다. 16UC1을 받는 환경으로 바뀌면 발행 규약의 단위를 확인한 뒤 변환한다.
  5. 영상과 깊이의 크기·시각·프레임을 검사하고 경계가 겹치는지 표시한다. 동일 크기·같은 frame_id·D=0만으로 픽셀 정렬을 확정하지 않는다. 물체 경계의 RGB/깊이 중첩과 센서 발행 설정을 함께 확인한다.

이상적인 핀홀 입력인 현재 시뮬레이션은 K와 P의 왼쪽 3×3이 같았다. 일반적으로 원본 영상은 K·D, 보정된 영상은 해당 영상의 P를 사용한다. 영상을 줄이면 깊이와 픽셀 좌표를 같은 크기로 맞추고 초점거리·주점도 같은 비율로 조정한다.

# 콜백 내부의 처리 순서 — 함수 내부는 직접 구현한다.
def on_rgbd(rgb_msg, depth_msg):

시뮬레이션에서는 학생 노드에 use_sim_time:=true를 설정한다. 관측 시각은 메시지의 stamp, 연산 시간은 time.perf_counter()로 구분한다. 무거운 특징점 처리가 구독을 막으면 제한된 크기의 작업 큐로 분리하고 누락 수를 기록한다.

산출물 / 통과 기준

동기화된 RGB·깊이 화면과 10초 이상 로그를 제출한다. 로그에는 rgb_count, depth_count, paired_count, dt_ms, valid_depth_ratio가 있어야 한다. 수신량 차이와 짝이 없는 프레임을 어떻게 처리했는지 설명한다.

02 · 특징점과 3차원 점

개념: 특징점은 다음 영상에서도 다시 찾기 쉬운 지점이다. 특징 기술자는 주변 모양을 숫자로 표현한다. 대응점은 두 영상에서 같은 실제 지점이라고 판단한 쌍이다.

  1. RGB를 그레이스케일로 바꾸고 cv2.ORB_create로 특징점·기술자를 구한다. 처음에는 최대 특징점 1,500~2,000개 정도로 시작하고 처리 시간과 분포를 관찰한다.
  2. 이전 기술자를 query, 현재 기술자를 train으로 두고 BFMatcher(NORM_HAMMING).knnMatch(..., k=2)로 비교한다. 이웃이 2개 없는 경우를 건너뛴다. 첫 거리 < 0.75×둘째 거리 같은 비율 검사를 시작값으로 사용한다. 같은 현재 점으로 중복 연결되는 대응도 정리한다.
  3. 이전 특징점의 픽셀에서 이전 깊이를 읽는다. 유효 깊이는 유한하고 양수여야 한다. 경계에서 깊이가 급변하는 대응도 표시해 오차 원인을 분석한다.
  4. 이전 3차원 점과 현재 2차원 픽셀을 같은 인덱스로 묶는다. 두 배열에서 서로 다른 순서로 원소를 제거하면 PnP가 엉뚱한 대응을 입력받는다.

p_prev = [(u − cx) × Z / fx, (v − cy) × Z / fy, Z]

(u,v)는 이전 특징점의 픽셀 좌표이고 Z는 그 위치에서 읽은 깊이다. 예를 들어 관측한 카메라의 중심 픽셀 (640,360)에서 깊이가 2 m이면 점은 (0,0,2) m다. Optical 좌표계는 x가 오른쪽, y가 아래, z가 전방이다.

프레임 자료구조에는 stamp, keypoints, descriptors, points3d, depth_valid_mask, camera_model을 보관한다. 깊이 무효점은 마스크로 관리하고, 압축한 대응 목록에서도 원래 특징점 인덱스를 추적할 수 있게 한다.

산출물 / 통과 기준

두 영상에 매칭 선을 그리고 features, matches, valid_3d_pairs를 기록한다. 복원한 3차원 점을 이전 영상에 다시 투영해 원래 픽셀과 일치하는지 검산한다. 빈 기술자·깊이 0·NaN·영상 밖 좌표를 처리해야 한다.

확인 질문: 현재 영상의 깊이를 이전 픽셀 위치에서 읽으면 왜 안 되는가?

03 · 이동 추정과 Visual Odometry

개념: PnP는 3차원 점들이 현재 영상의 어느 위치에 보이는지를 이용해 회전과 이동을 구한다. 재투영 오차는 추정한 자세로 투영한 픽셀과 실제 관측 픽셀 사이의 거리다.

  1. solvePnPRansac(points3d_prev, pixels2d_cur, K, distortion)으로 변환과 inlier(추정을 지지하는 대응점)를 구한다. 보정된 핀홀 입력일 때만 왜곡을 0 또는 None으로 둔다.
  2. 성공 플래그 외에 inlier 수·비율·화면 분포·재투영 오차를 검사한다. 시작값 예시는 inlier 30개 이상, 비율 0.4 이상, RANSAC 재투영 한계 3 px다. 실제 로그로 조정하고 근거를 적는다. 알고리즘의 수학적 최소 대응 수와 실습의 품질 기준은 다르다.
  3. 필요하면 inlier만으로 자세를 정제한다. 회전·이동을 4×4 동차변환 행렬로 만들고, 아래 방향 규약으로 누적한다.

가장 먼저 확인할 것은 변환 방향이다

T_A_B는 B 좌표의 점을 A 좌표로 바꾼다. PnP에 이전 카메라의 3차원 점과 현재 픽셀을 넣으면 결과는 T_cur_prev다. 카메라의 세계 자세를 누적할 때는 이 변환을 뒤집는다.

# W: 처음 카메라의 좌표계. 첫 자세는 단위행렬이다.
T_W_first = I
T_W_cur = T_W_prev @ inverse(T_cur_prev)

# prev 대신 키프레임 ref를 추적하면 같은 규칙을 사용한다.
T_W_cur = T_W_ref @ inverse(T_cur_ref)

검산 예: 회전 없이 카메라가 자신의 전방으로 0.1 m 이동하면 정지한 점의 현재 z는 0.1 m 줄어든다. PnP의 z 이동은 약 −0.1 m, 역변환으로 누적한 카메라 위치 변화는 +0.1 m가 되어야 한다.

카메라 궤적을 몸체 궤적으로 바꾼다

몸체 기준은 base_footprint다. Optical의 z 전방과 몸체의 x 전방을 숫자만 복사해서 연결하지 않는다. 영상 시각의 TF를 조회한다.

mount = tf_buffer.lookup_transform(
    "base_footprint", rgb_msg.header.frame_id,
    rclpy.time.Time.from_msg(rgb_msg.header.stamp))

# O: 시작 몸체 기준 student_odom. W: 시작 카메라 기준.
# M0 / Mk: 각 시각의 몸체←카메라 변환
T_O_base_k = M0 @ T_W_camera_k @ inverse(Mk)

초기 몸체 기준으로 바꾸면 첫 몸체 자세는 단위행렬이 된다. 머리가 움직일 때 M0와 Mk는 다르다. 해당 시각의 TF가 아직 없으면 짧게 대기하거나 프레임을 건너뛰고 사유를 기록한다. 움직이는 머리에서 최신 TF를 과거 영상에 대입하지 않는다.

추적 상태를 명시한다

INIT → TRACKING → LOST 상태를 둔다. 대응 부족, 품질 기준 미달, TF 누락을 구분한다. 실패한 프레임을 성공한 0 이동으로 발행하지 않는다. 마지막 유효 참조나 저장된 키프레임과 다시 매칭해 복구하고, 복구가 불가능해 새 구간을 시작하면 이전 궤적에 임의로 이어 붙이지 않는다.

산출물 / 통과 기준

/student_vslam/odom, /student_vslam/path와 stamp, state, matches, inliers, inlier_ratio, reproj_px, processing_ms 로그를 제출한다. 정지 시 흔들림, 직진 부호, 회전 방향을 확인하고 실패 구간을 궤적에서 구분한다.

확인 질문: PnP 결과를 그대로 누적했을 때 궤적 방향이 반대가 되는 이유는 무엇인가?

04 · 키프레임과 지도

개념: 모든 영상을 같은 비중으로 저장하면 계산량이 커진다. 키프레임은 장면을 대표하는 관측이다. 자신의 위치와 그 위치에서 본 점들을 함께 기억한다.

  1. 첫 유효 프레임을 K₀로 저장한다. 마지막 키프레임에서 충분히 이동·회전했거나 관측 겹침이 줄어들 때 새 키프레임을 선택한다. 예시 출발점은 0.25 m 또는 10°다. 추적에 실패한 프레임은 등록하지 않는다.
  2. id, stamp, descriptors, pixels, local_points, T_odom_base_raw, T_base_camera를 저장한다. 루프 검증용 특징점과 지도 표시용 점군은 분리해도 된다.
  3. 깊이를 역투영한 점들을 키프레임의 카메라 좌표에 보관한다. 표시할 때 지도 좌표로 변환한다. 지도용 깊이는 간격을 두고 샘플링하고, 같은 voxel(공간 격자)에 들어온 점을 줄여 메모리·표시 부하를 관리한다.
  4. 원본 VO 자세와 나중에 보정할 자세를 별도로 둔다. 루프가 아직 없을 때는 보정 자세를 원본 자세에서 초기화한다.
p_map = T_map_base_i @ T_base_camera_i @ p_camera_i

# 지도는 저장한 지역 관측에서 매번 재구성할 수 있어야 한다.
map_points = merge_and_downsample(
    transform_each_keyframe(local_clouds, corrected_poses))

같은 벽이 얇게 겹치면 좌표 변환과 자세 추정이 대체로 일관된다. 이중 벽은 드리프트뿐 아니라 시간 차이·잘못된 카메라 모델·반대 방향 변환으로도 발생한다. 기울어진 바닥은 optical↔몸체 변환부터 확인한다.

이 단계의 지도는 PointCloud2로 충분하다. 자유 공간을 판정하는 OccupancyGrid나 Nav2 Costmap은 별도 구현이다. 점군이 보이는 상태에서 재방문 관측을 어떻게 이용할지 다음 단계로 연결한다.

산출물 / 통과 기준

키프레임 목록·궤적·점군 지도를 저장한다. 한 키프레임의 자세를 바꿔 재구성했을 때 그 프레임의 관측도 함께 이동하는지 확인한다. 이미 세계 좌표로 바꾼 점에 자세를 다시 곱하지 않아야 한다.

확인 질문: 지도 점만 저장하고 관측 당시 자세를 버리면 루프 보정이 왜 어려워지는가?

05 · 루프 검증과 포즈 그래프

개념: 포즈 그래프의 점은 키프레임 자세, 연결선은 두 자세 사이의 상대 이동 관측이다. 순서대로 얻은 이동만 사용하면 오차가 누적된다. 재방문 관측은 떨어져 있던 두 시점 사이에 새로운 제약을 준다.

1. 장소 후보를 찾고 실제로 같은 장소인지 검증한다

최근 키프레임을 제외한 과거 프레임의 특징 기술자와 비교해 후보를 만든다. 시간 간격·특징점 일치 정도·공간적 분포를 기록한다. 매칭 수만으로 채택하지 않고, 과거 3차원 점과 현재 픽셀로 PnP·RANSAC을 다시 수행해 상대 자세를 검증한다. 반복 무늬에서 생긴 잘못된 후보도 기각 기록에 남긴다.

원본 VO의 위치가 가깝다는 조건만으로 후보를 제한하면 드리프트가 큰 실제 재방문을 놓칠 수 있다. 후보 생성에 외형 정보를 활용하고, 엄격한 기하 검증으로 최종 제약을 고른다.

2. 몸체 기준의 상대 관측으로 그래프를 구성한다

# Xi: 지도 기준 키프레임 i의 몸체 자세, Xj도 동일한 규약
# Eij: 몸체 j의 좌표를 몸체 i로 바꾸는 상대 관측
# 순차 제약은 보정 전 원본 VO에서 한 번 만든다.
Eij = inverse(T_odom_base_i_raw) @ T_odom_base_j_raw

# 루프: PnP 결과가 T_Cj_Ci일 때 카메라 변환을 몸체 변환으로
Eij_loop = M_i @ inverse(T_Cj_Ci) @ inverse(M_j)
# M_i = T_base_i_camera_i, M_j = T_base_j_camera_j

관측 Eij를 만든 뒤 평면 이동 x·y·yaw로 표현한다. 이미 보정한 자세의 차이로 순차 관측을 다시 만들면 원래 측정이 사라진다. 관측 제약과 최적화할 자세를 분리해 보관한다.

3. 첫 자세를 고정하고 나머지를 최적화한다

각 키프레임을 Xi = SE2(xi, yi, θi)로 둔다. z·roll·pitch는 평면 주행 가정에 따라 고정한다. 첫 노드 X₀를 고정하지 않으면 전체 지도가 함께 이동·회전해도 같은 비용이 된다.

predicted_ij = inverse(Xi) @ Xj
error_ij = inverse(Eij) @ predicted_ij
residual_ij = [error_ij.x / sigma_xy,
               error_ij.y / sigma_xy,
               wrap_angle(error_ij.yaw) / sigma_yaw]

# X0는 최적화 변수에서 제외한다.
# 모든 순차·루프 제약의 residual을 모아 최소화한다.
solution = scipy.optimize.least_squares(residuals, initial_variables,
                                       loss="huber")

wrap_angle은 각도를 −π~π로 정리한다. sigma_xy(m)와 sigma_yaw(rad)는 병진·회전 오차의 가중치를 정하는 양수다. 시작값과 변경 이유를 기록한다. 강건 손실은 큰 잔차의 영향을 줄이지만 잘못된 루프를 자동으로 해결해 주지는 않는다.

4. 보정된 지도와 현재 자세를 갱신한다

보정한 키프레임 자세로 실습 4의 지역 점군을 다시 변환한다. 현재 프레임이 마지막 키프레임 k에 연결되어 있으면 그 상대 움직임을 유지한다.

T_map_base_cur = Xk_corrected @ inverse(T_odom_base_k_raw) @ T_odom_base_cur_raw

원본 VO는 student_odom, 보정 결과는 student_map 출력으로 유지한다. 지도 보정 시 자세가 달라지는 것과 프레임 간 VO 추적 실패를 구분할 수 있어야 한다.

산출물 / 통과 기준

검증을 통과한 재방문 제약, 기각 사례, 그래프 비용의 보정 전후 값, 지도·궤적 비교를 제출한다. 첫 노드는 고정되고 원본 VO는 보존되어야 한다. 루프가 없는 데이터에서는 억지로 출발점에 닫히도록 만들지 않는다.

확인 질문: 같은 복도의 반복 무늬를 다른 장소와 잘못 연결하면 왜 전체 지도가 휘는가?

06 · 재현 가능한 비교와 평가

개념: 결과 그림 하나만으로 추정기의 성능을 판단하기 어렵다. 같은 관측을 반복 입력하고, 보정 기능의 유무와 실패 구간을 분리해 측정한다.

입력을 한 번 기록하고 같은 자료를 재생한다

교수자가 제공한 주행 데이터 또는 허용된 조작 인터페이스로 수집한 데이터를 사용한다. 정지·직진·제자리 회전·재방문 구간을 포함하고, 각 구간의 시작/종료 시각을 기록한다. 초기 구현에서는 머리 자세를 고정한다.

# 실행 중인 ALICE M1과 같은 ROS 환경에서 기록한다.
# 수집이 끝나면 Ctrl+C로 종료한다. 데이터에는 속도 명령을 포함하지 않는다.
ros2 bag record --use-sim-time -o m1_vslam_lab --topics \
  /aeirobot/vslam_left_image \
  /aeirobot/vslam_depth \
  /aeirobot/vslam_left_camera_info \
  /tf /tf_static /clock \
  /aeirobot/odometry /odometry/filtered /aeirobot/sim/gt_odom

ros2 bag info m1_vslam_lab

저장된 RGB·깊이·CameraInfo·동적 TF·정적 TF의 메시지 수를 확인한다. 시뮬레이션 시각으로 기록해야 재생 시각과 센서 헤더가 일관된다. 정적 TF가 없는 bag으로는 카메라 장착 변환을 재구성할 수 없다.

재생은 교수자가 지정한 별도 ROS 도메인에서 수행한다. 아래 123은 예시이며, 해당 도메인에 기존 노드가 없는지 먼저 확인한다. 모든 재생·학생 노드·RViz 터미널에 같은 설정을 적용한다. 실행 중인 원본 환경의 센서·TF·시계와 bag을 섞지 않는다.

# 재생용 터미널마다 설정한다. 원본 ALICE M1 프로세스 설정은 유지한다.
export ROS_DOMAIN_ID=123
export ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST

# 먼저 자신의 노드와 RViz를 use_sim_time:=true로 실행한다.
# 패키지·실행 파일을 student_vslam / slam_node로 등록한 경우의 예시다.
ros2 run student_vslam slam_node --ros-args -p use_sim_time:=true

# 같은 재생용 도메인의 다른 터미널에서 실행한다.
# --clock은 기록 시각으로 시계를 만들며 bag의 기존 /clock 재생을 제외한다.
ros2 bag play m1_vslam_lab --clock --rate 0.5

위 학생 실행 파일은 직접 작성·등록할 프로그램의 예시다. 이 안내 페이지가 완성된 SLAM 노드를 제공하는 것은 아니다. bag을 다시 처음부터 재생할 때는 학생 노드의 상태·TF 버퍼·로그를 초기화한다. 재생 속도를 낮춘 결과는 구현 확인용으로 표시하고, 처리 성능은 연산 시간과 실제 입력 처리량으로 따로 보고한다.

VO와 SLAM을 같은 조건으로 비교한다

동일 bag에 같은 프론트엔드 파라미터와 난수 시드를 적용한다. A는 루프 보정을 끄고, B는 켠다. 기록한 동기화 쌍의 시각 목록도 비교한다. 처리 지연 때문에 입력 자체가 달라졌다면 그 차이를 보고하거나 같은 프레임 목록으로 다시 비교한다.

측정 항목계산 / 해석
입력 손실각 입력 수·동기화 쌍 수·처리한 쌍 수를 함께 기록한다. 센서 미수신과 추적 실패를 구분한다.
추적 실패율초기화 이후 처리한 쌍 중 LOST로 판정한 쌍의 비율. 누락 구간을 오차 계산에서 제외했다면 길이도 표시한다.
프론트엔드 품질inlier 수·비율·재투영 오차 중앙값. 어떤 구간에서 악화되는지 시각과 함께 표시한다.
궤적 오차GT와 몸체 기준·시각·초기 원점을 맞춘 평면 위치 RMSE(m), yaw 오차(deg). RGB-D 결과의 척도를 임의로 맞춰 오차를 감추지 않는다.
재방문·지도 일관성같은 벽의 겹침, 재방문 구간의 위치 차이, 루프 채택·기각 수, 그래프 비용 전후를 함께 확인한다.
처리 시간프레임 연산 시간의 중앙값·95백분위수(ms), 처리 Hz, 큐 누락 수. bag 재생 속도와 하드웨어 조건을 적는다.

기준 궤적을 맞추는 순서

  1. GT의 child는 현재 robot_root, 학생 출력의 기준점은 base_footprint에 해당한다. 모델에서 두 기준점의 고정 변환을 확인해 T_gt_base = T_gt_root @ T_root_base로 바꾼다. frame 이름이 odom으로 같아도 서로 같은 원점이라고 가정하지 않는다.
  2. 공통 시작 시각 t₀를 정해 각각 inverse(T(t₀)) @ T(t)로 초기화한다. 영상 시각에 기준 궤적을 보간하고, 보간할 수 없는 긴 공백은 별도로 표시한다. 방향 보간은 quaternion 또는 각도 래핑을 고려한다.
  3. 추정·기준의 공통 유효 시각에서 평면 위치 오차를 계산한다. 동일한 초기 정렬을 VO와 SLAM에 적용한다. 루프 보정 효과는 공통 키프레임 시각의 원본 자세와 최종 보정 자세로도 비교한다.

GT의 기준점 변환을 확인할 수 없다면 절대 오차를 측정했다고 보고하지 않는다. 바퀴·EKF와의 차이는 추정기 사이의 차이이며 정답과의 차이가 아니다. 실제로 같은 위치에 복귀했는지 확인되지 않은 주행의 시작–끝 거리도 드리프트로 단정하지 않는다.

산출물 / 통과 기준

같은 데이터의 VO/SLAM 비교표, 보정 전후 궤적·지도, 실패 분석을 제출한다. 오차가 줄지 않은 경우도 데이터와 근거를 남긴다. 시뮬레이션에서 검증한 결과와 실제 센서 환경에서 검증한 결과를 구분한다.
